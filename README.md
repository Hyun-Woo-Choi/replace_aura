# WatchWell ⌚️

> A watchOS app that turns Apple Watch health data into personalized **stress** and **sleep** metrics, and uses reinforcement learning to recommend recovery actions that work for each user.

⚠️ This is a personal research and learning project, not a medical device. It must not be used for diagnosis or treatment.

---

## 1. Overview

Apple Watch collects rich physiological signals such as heart rate, heart rate variability (HRV), and sleep stages, but offers few personalized metrics that answer "how am I doing right now?" WatchWell aims to:

- Collect physiological data from HealthKit and compute state **relative to a personal baseline**
- Surface a stress index and sleep score on the watch and in complications
- Recommend recovery actions (breathing, rest, a short walk, etc.) with **reinforcement learning (contextual bandit)**, using the user's response as the reward
- Summarize the numbers as natural-language insights with the **Claude API**

## 2. Core Features

| Feature | Description |
|---|---|
| Stress Index (0–100) | Computed from HRV, resting heart rate, and respiratory rate relative to the personal baseline |
| Sleep Score (0–100) | Based on sleep stages (Core/Deep/REM), sleep efficiency, and bedtime consistency |
| Recovery Recommendations | Chooses the best intervention for the current state (context) and learns from the outcome |
| Daily/Weekly Insights | Short summaries and interpretation generated by Claude from aggregated metrics |
| Complication | Check the stress index directly from the watch face |

## 3. Metric Definitions

### 3.1 Stress Index

Apple does not expose a stress score, so it is estimated from physiological signals.

```
z_hrv  = (HRV_now  - HRV_baseline)  / HRV_std        # lower HRV -> higher stress
z_rhr  = (RHR_now  - RHR_baseline)  / RHR_std        # higher resting HR -> higher stress
z_resp = (Resp_now - Resp_baseline) / Resp_std

raw    = -w1 * z_hrv + w2 * z_rhr + w3 * z_resp
stress = 100 * sigmoid(raw)
```

- Baseline: median / standard deviation over a rolling 14–30 day window
- Initial weights (w1, w2, w3) are rule-based, then calibrated with self-reported labels ("Are you feeling stressed right now?")
- Data during and right after workouts is excluded, so exercise-driven heart rate isn't mistaken for stress

### 3.2 Sleep Score

| Component | Initial Weight |
|---|---|
| Total sleep time (vs. goal) | 35% |
| Sleep efficiency (time asleep / time in bed) | 20% |
| Deep + REM proportion | 20% |
| Bedtime and wake-time consistency | 15% |
| Deviation in sleeping heart rate and wrist temperature | 10% |

## 4. Machine Learning Design

Computing metrics and recommending actions are different kinds of problems, so they use different methods.

| Phase | Problem | Method |
|---|---|---|
| Phase 1 | Metric computation | Rule-based + personal baseline normalization |
| Phase 2 | Metric calibration | Supervised learning on self-reported labels (logistic regression / gradient boosting) |
| Phase 3 | Recovery recommendations | **Reinforcement learning: contextual bandit** (LinUCB or Thompson Sampling) |

### 4.1 Reinforcement Learning Setup (Phase 3)

- **State (context)**: current stress index, previous night's sleep score, time of day, day of week, recent activity level
- **Actions**: `1-min breathing` · `3-min breathing` · `short walk` · `drink water` · `no notification`
- **Reward**: weighted sum of HRV recovery within 30–60 minutes after the intervention and user feedback (👍/👎)
- **Exploration**: heavier exploration early on, shifting toward exploitation as data accumulates

> Stress and sleep metrics are estimation problems, so supervised and unsupervised learning fit them best. Reinforcement learning is applied where there is an **action → outcome → reward** loop, such as deciding which action to recommend. Because per-user data is sparse, the project starts with a contextual bandit rather than a full MDP.

## 5. How Claude Is Used

Claude serves as an **interpretation and explanation layer**, not as the model being trained.

- Generates natural-language daily/weekly summaries ("You slept less than usual last night, and your HRV this afternoon is below your baseline…")
- Briefly explains why an action was recommended
- Assists during development with code, feature design, and experiment analysis

**Privacy principle**: only **aggregated metrics** are sent to the Claude API, never raw data, and only after explicit user consent.

## 7. HealthKit Data Used

| Type | Identifier |
|---|---|
| Heart rate variability | `HKQuantityTypeIdentifier.heartRateVariabilitySDNN` |
| Resting heart rate | `HKQuantityTypeIdentifier.restingHeartRate` |
| Heart rate | `HKQuantityTypeIdentifier.heartRate` |
| Respiratory rate | `HKQuantityTypeIdentifier.respiratoryRate` |
| Blood oxygen | `HKQuantityTypeIdentifier.oxygenSaturation` |
| Sleeping wrist temperature | `HKQuantityTypeIdentifier.appleSleepingWristTemperature` |
| Sleep analysis | `HKCategoryTypeIdentifier.sleepAnalysis` (Core / Deep / REM / Awake) |
| Mindful sessions | `HKCategoryTypeIdentifier.mindfulSession` |
| Workouts | `HKWorkoutType` (used to exclude exercise windows from stress calculation) |

Updates are handled with `HKObserverQuery` + `enableBackgroundDelivery`, and incremental fetches with `HKAnchoredObjectQuery`.

## 10. Getting Started

### Requirements

- Xcode 16 or later
- A device on iOS 18+ / watchOS 11+ (the simulator has no real physiological data, so testing there is limited)
- Apple Developer account (required for the HealthKit capability)
- Python 3.11+ (for ML experiments)
- Anthropic API key (for the insights feature)

### Installation

```bash
git clone https://github.com/<your-id>/WatchWell.git
cd WatchWell

# ML experiment environment
cd ml
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Backend (optional)
cd ../backend
cp .env.example .env   # set ANTHROPIC_API_KEY and CLAUDE_MODEL
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### Xcode Setup

1. Generate the project with [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen && xcodegen generate`), then open `WatchWell.xcodeproj`
2. Add **Signing & Capabilities → HealthKit** to both the iOS and watchOS targets (enable Background Delivery)
3. Add the permission descriptions to `Info.plist`
   - `NSHealthShareUsageDescription`
   - `NSHealthUpdateUsageDescription`
4. Pair a physical device and build

## 12. Limitations and Caveats

- **HRV sampling frequency**: Apple Watch measures HRV only a few times a day in the background, which limits real-time stress estimation. Heart-rate-based estimates are used as a supplement.
- **Cold start**: establishing a personal baseline takes about two weeks; the UI indicates lower confidence during this period.
- **Reward noise**: HRV is affected by sleep, caffeine, exercise, and more, so the reinforcement learning reward is noisy.
- **Privacy**: health data may not be used for advertising or sold, and any external transfer must follow App Store Review Guideline 5.1.3 (Health and Health Research) and obtain user consent.
- **Not medical**: all metrics are wellness information for reference only.
